---
name: sidebar
description: Register a deferred request or an active guiding constraint without derailing the current focused work
---

The user has invoked /sidebar in their message alongside approving a current task. Do not let the sidebar derail the current work. Determine which of two modes applies:

## Mode 1: Deferred item (question, follow-up request, concern)
*Signals: asks a question, requests an additional action, raises a concern to revisit*

1. **Acknowledge briefly** — one sentence max, e.g. "Noted, I'll come back to that."
2. **Continue with the current task** uninterrupted.
3. **Return to the sidebar** after the task is fully done — restate what was set aside, then address it.

## Mode 2: Active constraint (reference, reminder, guiding concept)
*Signals: "remember that...", "keep in mind...", points to a package/pattern/convention to follow*

1. **Acknowledge briefly** — one sentence max, e.g. "Got it, I'll keep that in mind."
2. **Apply the constraint throughout the current task** — let it guide decisions without stopping to discuss it.
3. **Confirm at the end** — one sentence noting how the constraint was applied (or flag if it created a conflict).

If the aside contains both types, handle each accordingly.
